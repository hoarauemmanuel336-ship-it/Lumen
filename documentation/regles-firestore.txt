CE QUE CES RÈGLES FONT, EN UNE PHRASE
Toi seul, connecté avec ton adresse, peux lire et écrire quoi que ce
soit ; pour tout autre compte, et pour qui n'est pas connecté, la base
est fermée.


POURQUOI CE VERROU EN PLUS DE LA PORTE À MOT DE PASSE
La porte protège les pages du site. Mais la base de données (Firestore)
est chez Google, pas chez Netlify : sans ces règles, quelqu'un qui
connaîtrait l'adresse du projet pourrait encore lire les articles, les
ressources et les commentaires « publiés ». Avec elles, même ça est fermé.


LE PAS À PAS

1. Va sur https://console.firebase.google.com et ouvre le projet
   « lumen-veritatis ».

2. Dans la colonne de gauche, clique sur « Firestore Database ».

3. En haut de la page, choisis l'onglet « Règles » (ou « Rules »).

4. Sélectionne TOUT ce qui s'y trouve déjà et efface-le.

5. Copie le bloc encadré ci-dessous, du premier « rules_version » jusqu'à
   la dernière accolade, et colle-le à la place.

6. Clique sur « Publier » (bouton bleu, en haut à droite). L'effet est
   immédiat, il n'y a rien à redéployer sur Netlify.

7. Reviens sur le site, connecté : tout doit fonctionner comme avant
   (Mémoriser, Articles, Ressources, commentaires dans la Bible).


LE TEXTE À COLLER
────────────────────────────────────────────────────────────────────
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Le seul compte admis : le tien.
    function proprietaire() {
      return request.auth != null
        && request.auth.token.email == "hoarauemmanuel336@gmail.com"
        && request.auth.token.email_verified == true;
    }

    // Tout, partout : ton espace, les réglages, le contenu, les
    // articles, ressources, commentaires et images « publiés ».
    match /{document=**} {
      allow read, write: if proprietaire();
    }
  }
}
────────────────────────────────────────────────────────────────────


SI QUELQUE CHOSE NE S'AFFICHE PLUS

Vérifie d'abord que tu es bien connecté sur la page (avec ton adresse
Gmail). Les pages ne lisent plus rien pour un visiteur non connecté :
c'est voulu.

Si tu es connecté et que rien ne se charge, la cause la plus probable
est la ligne « email_verified ». Elle exige que l'adresse ait été
confirmée. La solution la plus propre : se connecter une fois avec le
bouton « Continuer avec Google », qui confirme l'adresse de lui-même.
La plus rapide : retirer la ligne
« && request.auth.token.email_verified == true » et republier.


CE QU'IL FAUT SAVOIR

L'ADRESSE EST LA CLÉ. Si l'adresse du compte change un jour, il faudra
la changer ici aussi (un seul endroit désormais).

LES AUTRES COMPTES. Si d'autres personnes s'étaient créé un compte, leurs
données restent dans la base mais plus personne (eux compris) n'y a
accès. Pour faire le ménage : Firebase → Authentication → Users, et
supprimer les comptes qui ne sont pas le tien.

« PUBLIER » GARDE UN SENS. Un article, une ressource ou un commentaire
« publié » n'est plus visible du public, seulement de toi, sur tous tes
appareils. Les boutons restent, rien n'est cassé.

CE QUE ÇA COÛTE. Rien. Le projet reste sur le forfait gratuit.
