RÈGLES DE SÉCURITÉ FIRESTORE — LUMEN VERITATIS
Version « chacun son espace »
════════════════════════════════════════════════════════════════════

CE QUE CES RÈGLES FONT, EN UNE PHRASE
Toi, connecté avec ton adresse, tu lis et écris tout ; tout autre
compte connecté, à l'adresse confirmée, lit et écrit dans son propre
espace (ses notes, son Mémoriser, sa lecture d'Étude, ses questions à
l'IA, la mémoire de l'IA à son sujet), et nulle part ailleurs ; pour qui
n'est pas connecté, la base est fermée.


POURQUOI CE VERROU EN PLUS DE LA PORTE À MOT DE PASSE
La porte protège les pages du site. Mais la base de données (Firestore)
est chez Google, pas chez Netlify : sans ces règles, quelqu'un qui
connaîtrait l'adresse du projet pourrait lire tes données. Avec elles,
chaque compte ne voit que son propre espace, et le tien reste à toi seul.


LE PAS À PAS

1. Va sur https://console.firebase.google.com et ouvre le projet
   « lumen-veritatis ».

2. Dans la colonne de gauche, clique sur « Firestore Database ».

3. En haut de la page, choisis l'onglet « Règles » (ou « Rules »).

4. Sélectionne TOUT ce qui s'y trouve déjà et efface-le.

5. Copie le bloc encadré ci-dessous, du premier « rules_version » jusqu'à
   la dernière accolade, et colle-le à la place.

6. Clique sur « Publier » (bouton bleu, en haut à droite). L'effet est
   immédiat, il n'y a rien à redéployer sur Netlify.

7. Reviens sur le site, connecté : tout doit fonctionner comme avant
   (Bible, Mémoriser, Étude, Articles).


LE TEXTE À COLLER
────────────────────────────────────────────────────────────────────
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // Ton compte.
    function proprietaire() {
      return request.auth != null
        && request.auth.token.email == "hoarauemmanuel336@gmail.com"
        && request.auth.token.email_verified == true;
    }

    // Un compte connecté, à l'adresse confirmée, chez lui.
    function chezSoi(uid) {
      return request.auth != null
        && request.auth.uid == uid
        && request.auth.token.email_verified == true;
    }

    // Toi : tout, partout (ton espace, les réglages, les anciennes
    // données communes).
    match /{document=**} {
      allow read, write: if proprietaire();
    }

    // Chacun : son propre espace, et rien d'autre.
    match /users/{uid}/{document=**} {
      allow read, write: if chezSoi(uid);
    }
  }
}
────────────────────────────────────────────────────────────────────


SI QUELQUE CHOSE NE S'AFFICHE PLUS

Vérifie d'abord que tu es bien connecté sur la page (avec ton adresse
Gmail). Les pages ne lisent rien pour un visiteur non connecté : c'est
voulu.

Si tu es connecté et que rien ne se charge, la cause la plus probable
est la ligne « email_verified ». Elle exige que l'adresse ait été
confirmée. La solution la plus propre : se connecter une fois avec le
bouton « Continuer avec Google », qui confirme l'adresse de lui-même.


CE QU'IL FAUT SAVOIR

L'ADRESSE EST LA CLÉ. Si l'adresse de ton compte change un jour, il
faudra la changer ici aussi (un seul endroit).

LES AUTRES COMPTES. Chaque compte a son espace sous son propre
identifiant : il n'y voit que ce qu'il y a mis, et ne voit rien du tien.
Les réglages et les anciennes données communes restent à toi seul, en
lecture comme en écriture.

LA PORTE RESTE FERMÉE. Tant que le mot de passe du site garde les pages,
personne d'autre n'arrive jusqu'à elles : ces règles préparent seulement
le jour où le site s'ouvrira.

CE QUE ÇA COÛTE. Rien pour l'instant. Le projet reste sur le forfait
gratuit, dont les limites se reverront si beaucoup de comptes s'en
servent.
