RÈGLES DE SÉCURITÉ FIRESTORE — LUMEN VERITATIS
À coller dans la console Firebase pour que la publication fonctionne.
════════════════════════════════════════════════════════════════════

CE QUE CES RÈGLES FONT, EN UNE PHRASE
Chacun est seul maître de son espace, et il existe à côté un espace public
que tout le monde peut lire mais que toi seul peux remplir.


POURQUOI IL FAUT LES POSER
Tant qu'elles ne sont pas en place, le bouton « Publier » échoue : Firebase
refuse d'écrire dans un endroit dont personne ne lui a dit qu'il existe.
Les articles restent alors privés, et le site continue de fonctionner
normalement pour tout le reste.


LE PAS À PAS

1. Va sur https://console.firebase.google.com et ouvre le projet
   « lumen-veritatis ».

2. Dans la colonne de gauche, clique sur « Firestore Database ».

3. En haut de la page, choisis l'onglet « Règles » (ou « Rules »).

4. Sélectionne TOUT ce qui s'y trouve déjà et efface-le.

5. Copie le bloc encadré ci-dessous, du premier « rules_version » jusqu'à
   la dernière accolade, et colle-le à la place.

6. Clique sur « Publier » (bouton bleu, en haut à droite). L'effet est
   immédiat, il n'y a rien à redéployer sur Netlify.

7. Reviens sur le site, ouvre un article et clique « Publier ». Ouvre
   ensuite lumenveritatis.net/articles.html dans une fenêtre de navigation
   privée, sans être connecté : l'article doit s'y lire.


LE TEXTE À COLLER
────────────────────────────────────────────────────────────────────
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // ── L'ESPACE DE CHAQUE COMPTE ──
    // Versets mémorisés, notes, surlignages, brouillons d'articles, images :
    // seul le compte concerné y entre, en lecture comme en écriture.
    match /users/{compte}/{reste=**} {
      allow read, write: if request.auth != null && request.auth.uid == compte;
    }

    // ── LES ARTICLES PUBLIÉS ──
    // Lisibles par tout le monde, même sans compte. Écrits par toi seul.
    match /public_articles/{article} {
      allow read: if true;
      allow write: if request.auth != null
                   && request.auth.token.email == 'hoarauemmanuel336@gmail.com';
    }

    // ── LES IMAGES DES ARTICLES PUBLIÉS ──
    // Mêmes règles : elles doivent être lisibles, sinon les articles
    // publiés afficheraient des cadres vides pour tout le monde sauf toi.
    match /public_medias/{media} {
      allow read: if true;
      allow write: if request.auth != null
                   && request.auth.token.email == 'hoarauemmanuel336@gmail.com';

      match /tranches/{tranche} {
        allow read: if true;
        allow write: if request.auth != null
                     && request.auth.token.email == 'hoarauemmanuel336@gmail.com';
      }
    }
  }
}
────────────────────────────────────────────────────────────────────


CE QU'IL FAUT SAVOIR

TON ADRESSE EST LA CLÉ. C'est l'adresse écrite dans les règles qui donne le
droit de publier, pas un mot de passe caché dans le site. Si tu changes un
jour l'adresse de ton compte, il faudra la changer ici aussi, aux trois
endroits. Personne ne peut créer un compte avec ton adresse : Firebase
refuse une adresse déjà prise.

UN BROUILLON N'EST JAMAIS EXPOSÉ. Publier ne « déverrouille » pas ton
brouillon : cela en recopie une version dans l'espace public. Ce qui n'a pas
été copié n'est pas lisible, il n'y a pas de règle à se tromper. Retirer un
article de la ligne efface la copie, images comprises.

LA MODIFICATION SUIT. Un article déjà publié que tu modifies est remis en
ligne à l'enregistrement, sans rien avoir à faire.

CE QUE ÇA COÛTE. Rien. Le projet est sur le forfait gratuit, aucune carte
n'est attachée, aucune facture n'est possible. La lecture publique consomme
des lectures Firestore, largement sous les cinquante mille par jour offertes.
