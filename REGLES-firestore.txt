RÈGLES DE SÉCURITÉ FIRESTORE — LUMEN VERITATIS
À coller dans la console Firebase pour que la publication fonctionne.
════════════════════════════════════════════════════════════════════

CE QUE CES RÈGLES FONT, EN UNE PHRASE
Chacun est seul maître de son espace, et il existe à côté des espaces
publics que tout le monde peut lire mais que toi seul peux remplir.


CE QUI CHANGE PAR RAPPORT AUX RÈGLES DÉJÀ EN PLACE
Rien n'est retiré. Les trois blocs existants (« users », « config »,
« contenu ») sont conservés mot pour mot. Quatre blocs sont ajoutés à la
fin : « public_articles » et « public_medias » pour les articles,
« public_ressources » et « public_res_medias » pour la section Ressources.
Sans eux, le bouton « Publier » échoue : Firebase refuse d'écrire dans un
endroit dont personne ne lui a dit qu'il existe.


LE PAS À PAS

1. Va sur https://console.firebase.google.com et ouvre le projet
   « lumen-veritatis ».

2. Dans la colonne de gauche, clique sur « Firestore Database ».

3. En haut de la page, choisis l'onglet « Règles » (ou « Rules »).

4. Sélectionne TOUT ce qui s'y trouve déjà et efface-le.

5. Copie le bloc encadré ci-dessous, du premier « rules_version » jusqu'à
   la dernière accolade, et colle-le à la place.

6. Clique sur « Publier » (bouton bleu, en haut à droite). L'effet est
   immédiat, il n'y a rien à redéployer sur Netlify.

7. Reviens sur le site, ouvre un article et clique « Publier ». Ouvre
   ensuite lumenveritatis.net/articles.html dans une fenêtre de navigation
   privée, sans être connecté : l'article doit s'y lire. Fais le même essai
   depuis Ressources.


LE TEXTE À COLLER
────────────────────────────────────────────────────────────────────
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {

    // ── L'ESPACE DE CHAQUE COMPTE ──
    // Versets mémorisés, notes, surlignages, brouillons d'articles,
    // images : seul le compte concerné y entre, en lecture comme en
    // écriture.
    match /users/{uid}/{doc=**} {
      allow read, write: if request.auth != null
        && request.auth.uid == uid;
    }

    // ── LES RÉGLAGES DU SITE ──
    // Lus par tout le monde (Mémoriser y prend ses catégories de base),
    // écrits par toi seul.
    match /config/{doc} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.token.email == "hoarauemmanuel336@gmail.com"
        && request.auth.token.email_verified == true;
    }

    match /contenu/{slug} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.token.email == "hoarauemmanuel336@gmail.com"
        && request.auth.token.email_verified == true;
    }

    // ── LES ARTICLES PUBLIÉS ──
    // Lisibles par tout le monde, même sans compte. Écrits par toi seul.
    match /public_articles/{doc=**} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.token.email == "hoarauemmanuel336@gmail.com"
        && request.auth.token.email_verified == true;
    }

    // ── LES IMAGES DES ARTICLES PUBLIÉS ──
    // Mêmes règles. Le « doc=** » couvre aussi les tranches dans
    // lesquelles une image est découpée pour tenir dans Firestore ;
    // sans elles, les articles publiés afficheraient des cadres vides
    // pour tout le monde sauf toi.
    match /public_medias/{doc=**} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.token.email == "hoarauemmanuel336@gmail.com"
        && request.auth.token.email_verified == true;
    }

    // ── LES RESSOURCES PUBLIÉES ──
    // Diagrammes, cartes, livres et liens. Mêmes règles que les articles.
    match /public_ressources/{doc=**} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.token.email == "hoarauemmanuel336@gmail.com"
        && request.auth.token.email_verified == true;
    }

    // ── LES FICHIERS DES RESSOURCES PUBLIÉES ──
    match /public_res_medias/{doc=**} {
      allow read: if true;
      allow write: if request.auth != null
        && request.auth.token.email == "hoarauemmanuel336@gmail.com"
        && request.auth.token.email_verified == true;
    }
  }
}

SI « PUBLIER » ÉCHOUE QUAND MÊME

La cause la plus probable est la dernière ligne de chaque bloc,
« email_verified ». Elle exige que l'adresse ait été confirmée par un
clic sur le lien reçu par courriel. Si le compte a été créé avec une
adresse et un mot de passe sans jamais confirmer, la condition est
fausse et Firebase refuse l'écriture, même au propriétaire.

Deux façons d'en sortir. La plus propre : se connecter une fois au site
avec le bouton « Continuer avec Google », en utilisant la même adresse.
Google confirme l'adresse de lui-même, et la condition devient vraie
pour de bon. La plus rapide : retirer les six lignes
« && request.auth.token.email_verified == true » et republier les règles.
La sécurité reste entière, car personne ne peut créer un compte avec
cette adresse, Firebase refuse une adresse déjà prise.


CE QU'IL FAUT SAVOIR

L'ADRESSE EST LA CLÉ. C'est l'adresse écrite dans les règles qui donne le
droit d'écrire, pas un mot de passe caché dans le site. Si l'adresse du
compte change un jour, il faudra la changer ici aussi, à chacun des six
endroits.

UN BROUILLON N'EST JAMAIS EXPOSÉ. Publier ne « déverrouille » pas un
brouillon : cela en recopie une version dans l'espace public. Ce qui n'a
pas été copié n'est pas lisible, il n'y a pas de règle à se tromper.
Retirer un article de la ligne efface la copie, images comprises.

LA MODIFICATION SUIT. Un article déjà publié que l'on modifie est remis en
ligne à l'enregistrement, sans rien avoir à faire.

CE QUE ÇA COÛTE. Rien. Le projet est sur le forfait gratuit, aucune carte
n'est attachée, aucune facture n'est possible. La lecture publique
consomme des lectures Firestore, largement sous les cinquante mille par
jour offertes.
